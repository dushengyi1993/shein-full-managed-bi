# 全托 BI 首版能力边界

## 当前支持

- 24 家全托店铺主数据与逐店证据隔离；
- “销量查询”权限包的只读探针历史；
- OpenAPI 抓取批次、错误、分页结果数量和脱敏响应证据；
- 店铺内 SKU / SKC / SPU / 供应商货号归并，以及基于强证据的跨店标准商品；
- 指定时间窗口、指定观察时点的 SKU 销量**数量快照**；
- 今日、昨日、近 7 日、近 30 日聚合，真实逐日趋势、店铺排行和标准商品排行；
- 商品目录与详情属性补充，但稳定 SKU 成员关系始终以销量 `number-list` 为准；
- PI / VI / JI 库存、仓库库存、缺货建议与字段覆盖；
- 采购单、采购单行、JIT 关系、交付单、交付单行与入仓里程碑；
- Webhook 验签、密文回执、异步解密、标准化事件、任务队列、授权门禁与运行心跳；
- 数据新鲜度、业务日期、店铺覆盖、来源批次、指纹和具体质量原因；
- 员工可读全部店铺，未来写入只允许本人 `PRIMARY / SUPPORT` 店铺；
- 本地开发、独立云端部署、数据库迁移、契约校验、定时同步、备份和 Git 版本管理。

“应用审核通过”“店铺完成授权”“手动申请了销量权限包”和“销量接口实际可读”是四件不同的事。只有最新的只读探针返回明确业务成功，才把该店视为 `GRANTED`；缺权限或抓取失败必须显示为缺数，不能显示为零销量。完整响应全部为零且平台不返回 `dt` 时属于合法零销量，但必须以明确的 `LEGAL_ZERO_UNANCHORED` 证据展示，不能伪造业务日期。

## 当前明确不支持

- 销售金额、GMV、成交额、币种换算；
- 消费者订单数量、明细、状态和消费者信息；
- 消费者退款、退货、取消订单和 COD 口径；
- 供货价、平台结算、费用、税费、回款和发票；
- 成本、毛利、净利、利润率；
- 没有独立字段样本的采购退货、商品合规、建议零售价和财务事实；
- 仅凭相同裸 SKU、标题相似或货号相似做跨店自动归并；
- Webhook 触发后的自动 OpenAPI 回查闭环；
- 由系统自动创建、变更或删除平台 Webhook 订阅；
- 任何商品、库存、采购、财务或营销写操作；
- 与半托生产事实源合并或相互写入。

门户中的采购、交付、库存、缺货和平台动态使用各自的只读事实；采购退货、合规、财务与自动化运营仍只展示已有证据、字段边界和下一步。页面存在不代表对应写能力可用，未接入字段不得显示虚构业务数。

销量页面和 API 只能使用“销量数量”或“件数”措辞，不能写“销售额”“消费者订单量”或“利润”。也不能用销量乘当前价格推导金额，因为价格和销量窗口并不具备同一历史口径。

## 读取与写入权限

- 登录员工读取的是同一份全店数据集，负责人和店铺只作为筛选维度；
- `VIEWER`、未分配店铺或缺少能力许可的员工不能写；
- 即使是管理员或运营人员，写入也必须同时满足全局写开关、仓库授权身份、显式能力许可和店铺分配；
- 当前服务器拒绝所有业务 mutation，SHEIN 平台写操作、Webhook 订阅写入和自动化执行均为关闭；
- 后续开放任何写动作时，仍须逐次执行实时读回、dry-run、明确确认、审计回执和结果回读。

## 全托与半托隔离

- 全托使用独立仓库迁移、表名、配置和应用凭据；
- 不复制半托大型 schema，不把半托 API 字段默认当作全托字段；
- 不把相同公司主体理解为相同应用、权限、店铺或数据授权；
- 如未来需要跨模式分析，只能在两个事实源各自完成探针、对账和质量检查后，通过新的只读映射层联合，不能直接互写事实表。

## 后续独立数据域

财务、消费者订单和未接入的运营域必须各自设计，不向销量或供应链事实表追加“顺手可用”的列：

- **财务域**：结算单、费用项、税费、回款、币种与汇率，拥有独立事实粒度和会计期间；
- **采购扩展域**：采购退货、异常处理和未覆盖里程碑，继续沿用独立单据状态机与数量口径；
- **订单域**：只有在获得独立订单权限并确认个人信息处理边界后再设计；
- 各域只通过稳定的店铺、SKU / 商品映射关联，并保留来源批次和对账状态。

新域上线前必须分别完成：官方接口确认、字段样本留证、权限探针、时间与状态口径、幂等策略、脱敏规则、历史回填方案和逐店对账。

## 安全与发布门槛

- 仓库不得包含数据库密码、OpenAPI secret、token、cookie、签名或浏览器 Profile；
- raw 与 ops JSON 在写库前必须脱敏，错误日志也遵守同一规则；
- 云端探针不得执行写接口；
- 数据库迁移必须在空库和重复执行场景验证；
- Portal 不得持有数据库或平台凭据；同步、物化和 Webhook 进程必须使用不同 Unix 与数据库身份；
- Webhook 空队列不等于进程健康，必须由 Receiver / Worker 新鲜心跳分别证明；
- 云端必须持续保留容量监控、备份恢复演练、最小权限账号和回滚方案；
- 未完成逐店探针与事实对账前，不宣称全托 BI 已成为生产事实源。
