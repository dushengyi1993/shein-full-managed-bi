# 全托 BI 门户信息架构与首版页面规划

最后更新：2026-08-08

## 1. 设计依据

全托门户沿用半托 BI 已验证的页面骨架：固定侧栏、顶部全局筛选、首页总控、业务域子页、系统健康和受控自动化入口。首版继续使用当前原生 HTML / CSS / JavaScript 和同源只读 API，不引入新的前端框架。

本次不复制半托业务指标。半托首页已有成交额、消费者订单、售后、利润、流量等事实域；全托首版使用 SKU 销量、商品、采购、交付、库存、缺货和 Webhook 各自的只读事实。没有独立事实的数据域仍只展示接入状态、所需证据和空状态，不能用示例金额或推导值填充。

## 2. 已解决的页面问题

- 固定侧栏、顶部筛选、业务域下钻和系统健康已经拆分；
- 首页回答“今天卖了多少、趋势如何、哪家店和哪个标准商品领先、数据是否可信”；
- 示例、空库、合法零销量、缺权限、部分覆盖与真实数据有不同文案；
- “应用审核、权限包、店铺授权、接口探针、事实入仓”保持为五个独立阶段；
- 员工默认读取全店数据，负责人/店铺/商品只作为全局筛选；
- 桌面与 390px 窄屏均无横向溢出。

## 3. 全局页面骨架

### 固定侧栏

侧栏负责一级导航、当前数据环境和关键接入状态。桌面端固定在左侧，窄屏变为顶部横向导航。

导航顺序：

1. 总控驾驶舱
2. 订单管理（可展开分组）
3. 销量分析
4. 商品分析
5. 库存与备货
6. 采购单
7. 平台动态
8. 运营工具
9. 系统管理

“订单管理 / ORDER”桌面端使用侧边浮层，390px 窄屏使用文档流内手风琴；固定子页为：

- 发货履约：发货订单、发货单列表、备货记录、运单报表；
- 退货异常：退货申请、退货列表、收货/退货异常；
- 服务质检：增值服务列表、质检报告。

`#fulfilment` 保持为第一子页并复用既有发货订单成果，其余九页统一读取
`order-management.json`，不复制或倒退既有实现。

### 顶部全局筛选

所有可读取销量事实的页面共用：

- 标准货号、SKC、SKU / 商品名搜索；
- 负责人筛选（只影响视图，不限制读取）；
- 店铺筛选；
- 时间口径：今日、昨日、近 7 日、近 30 日；
- 清空筛选；
- 当前数据环境与更新时间。

现有销量接口只提供预聚合窗口，不能把它伪装成任意日期范围。未来接入日粒度事实后，再升级为与半托一致的双日历。

## 4. 首页放什么

首页只回答五个问题，不放长明细：

1. **数据能不能看**：示例 / 实时、更新时间、只读状态。
2. **接入走到哪一步**：应用审核、销量权限包、店铺授权、接口探针、事实入仓。
3. **销量规模如何**：今日、昨日、近 7 日、近 30 日销量数量。
4. **哪里最值得先看**：销量最高店铺、销量最高 SKU、权限或数据阻断点。
5. **去哪里处理**：采购、交付、商品、销量、库存、平台动态和系统健康的快捷入口。

首页下半部分保留：

- 销量趋势；没有日粒度数据时显示明确空状态；
- 店铺销量 Top 榜；
- 标准商品销量 Top 榜；
- 业务域接入地图。

长表、完整排行、字段证据和操作流程全部下沉子页。

## 5. 子页面放什么

| 页面 | 回答的问题 | 首版内容 | 当前数据边界 |
| --- | --- | --- | --- |
| 采购单中心 | 哪些采购单处于什么状态？ | 状态聚合、采购单与行项目、时间和字段覆盖 | 独立采购事实；未知数量不补零 |
| 交付与入仓 | 哪些交付已创建、预约、在途或入仓？ | 交付里程碑、数量覆盖与交付明细 | 滚动窗口加未收货点查；不伪造历史完整性 |
| 商品与货号 | 哪些店内货号属于同一标准商品？ | 标准商品、店内身份、待归并货号和冲突 | 店内强键；跨店只接受强证据 |
| 销量分析 | 哪家店、哪个 SKU / 标准商品卖得更多？ | 四窗口、逐日趋势、完整排行与筛选 | 只有销量件数；缺数保持空值 |
| 库存与供给 | 哪些 SKU 缺货或库存覆盖不完整？ | 全托 PI / JI、仓库库存、缺货建议与对账；VI 仅作兼容诊断 | 请求集合来自稳定销量清单 |
| 采购退货 | 有哪些采购退货信号？ | 已知 Webhook/字段证据与接入边界 | 无独立完整事实时不显示业务数 |
| 合规与价格 | 哪些审核、合规或 RRP 事件需关注？ | 已标准化事件与待回查指令 | Worker 尚未自动完成回查 |
| 财务结算 | 平台结算、费用和回款是否一致？ | 会计期间和接入边界 | 当前无金额、结算、成本或利润事实 |
| 平台动态 | Webhook 是否在运行、事件是否积压？ | Receiver/Worker 心跳、队列、订阅回读、事件时间线 | 至少一次语义；订阅写入关闭 |
| 自动化运营 | 哪些问题可形成待办候选？ | 只读候选池、原因和证据 | 所有动作控件关闭 |
| 系统健康 | 今天的数据和权限能否放心使用？ | 数据集、销量、供应链、Webhook、覆盖和具体原因 | 不用空队列或合法零销量制造误报 |

## 6. 全托与半托的差异

- 半托已有消费者订单、售后、流量、评价、营销和利润事实；全托首版不展示这些指标。
- 全托一级业务域按应用申请范围组织：商品管理、商品合规、备货管理、库存管理、财务管理。
- 半托“营销中心”不直接复制到全托。只有确认全托对应权限、平台控制边界和真实字段后，才决定是否单独建设。
- 全托自动化优先围绕商品资料、合规、采购履约、库存和财务复核；任何写动作都必须保留权限检查、店铺归属、dry-run、明确确认、审计和结果回读。
- 全托与半托数据仓库、应用凭据、权限探针和事实表保持隔离。

## 7. v1 实现范围

- 重做为与半托同一设计家族的固定侧栏和顶部筛选布局；
- 使用 hash 路由实现 9 个一级入口及订单管理 10 个固定子页，不改变服务器安全路由；
- 总控、销量、商品、采购、交付、库存、平台动态和系统健康使用各自的只读事实；
- 合规、采购退货、财务和自动化运营提供真实边界与已有事件，不伪造业务数；
- 数据请求失败时在首屏显示错误，并保留重试；
- 示例数据在侧栏、顶部和内容区持续标记；
- 桌面和移动视口均可用；
- 保持 CSP、只读 HTTP 方法限制和敏感指标白名单。

### 7.1 独立采购查询与快照更新

- `/api/procurement` 是认证后的独立只读查询面，服务端执行负责人、
  店铺、文本、状态、关注类型、排序和有界分页；Portal 仍然不持有
  数据库连接或 SHEIN 凭据。
- 查询范围是物化器写入 `dashboard.json` 的采购状态和关注明细。响应
  同时返回 `total / returned / truncated`，页面必须使用“已物化范围命中”
  描述筛选结果；源明细截断时禁止称为仓库全量。
- `/api/events` 是认证后的同源 SSE 更新流。服务器只监听
  `dashboard.json` 的原子提升并广播无路径、无业务值的版本通知；一个
  共享 watcher 服务所有连接，最后一个客户端断开后释放 timer。
- 浏览器收到版本通知后重新请求 `/api/dashboard` 和当前采购查询。
  页面使用“快照自动更新”，不得称为 SHEIN 实时连接；事实时间和业务
  日期仍以响应字段为准。

### 7.2 独立销量查询与经营脉搏

- `/api/sales` 是认证后的独立只读查询面。负责人、店铺、搜索、商品
  身份、近 7 日/此前 23 日动量、排序以及店内商品/标准商品各自分页均
  在服务端执行；重复参数、未知负责人和越界页大小失败关闭。
- 查询只覆盖 `dashboard.json` 已白名单化的店铺、店内 SKU 和标准商品
  排行。响应分别返回物化命中数和 ranking `returned / total /
  truncated`；页面只能称“已物化范围命中”，不能称仓库或 SHEIN 全量。
- 首页“经营脉搏”不新增业务事实：它把已有销量窗口、采购/交付关注、
  库存风险、排行与数据质量压缩成四个可下钻判断。金额、消费者订单和
  不完整窗口不参与推导，合法零、未知、部分覆盖保持不同文案。

### 7.3 订单管理只读工作区

- `/api/orders?page=<pageId>` 是认证后的统一只读查询面；筛选、排序和分页均在服务端执行，
  未知参数、重复参数和写方法失败关闭。
- 九个新增子页共享固定合同和统一的加载、可用、空、部分、不可用状态。只有取得可验证
  数据合同且完整覆盖的页面才展示业务行；没有足够证据的页面返回 `503` 和具体原因，
  不猜接口、不把未知显示为零。
- 页面只允许查询和展开脱敏详情，不提供打印、取消、发货、备货、确认退货、签收、复议、
  自动确认等平台写操作。
- `order-management.json` 与核心 Dashboard 文件在同一 staging/promote 链路中原子提升；
  任一覆盖、分页、总数或去重门禁失败时保留旧版本，禁止发布半套快照。

## 8. 验收标准

- 首页不再出现完整长表，能在首屏看清数据状态、接入进度和四个销量指标；
- 9 个一级入口均可打开；订单管理可展开 10 个固定子页，当前子页有明确高亮；
- 负责人、店铺、商品搜索和时间口径会同步影响可用视图；
- 任何未接入业务域都不会显示虚构的零、金额、订单或利润；
- 示例数据与实时数据在视觉和文案上不可混淆；
- `/health`、`/api/dashboard`、`/api/procurement`、`/api/sales`、`/api/orders`、`/api/events`、
  静态资源、安全头和未知路径契约继续通过测试；
- 浏览器无控制台错误，桌面首屏与窄屏完成视觉验收。
