# 全托商品身份与货号归并运行手册

## 目标与边界

商品身份层只解决“哪些店内商品属于同一个标准商品、哪些 SKU 属于哪个变体”。它不会编辑 SHEIN 商品，也不会把店内货号、标题或裸平台编码直接当成跨店主键。

- 所有 OpenAPI 请求固定为只读 `POST /open-api/goods/spu-info`。
- 平台 SKU / SKC / SPU 只在店铺内是强键。
- 供应商货号、商家 SKU、标题和图片 URL 只能召回候选。
- EAN / UPC 位于 SKU 变体层，一个 SKU 可以有多条；只有通过 GTIN 校验位的条码才可作为强证据。
- 官方型号只接受商品属性 ID `1000546`，不能从标题或旧接口 `productNumber` 猜测。
- 电压、插头、容量、末级分类和关键尺寸冲突时禁止自动合并。
- 所有员工可查看全部店铺；将来的人工作业只允许写本人 `PRIMARY / SUPPORT` 店铺。当前 SHEIN 写操作全局关闭。

## 三段运行流程

### 1. 冻结证据

先执行 dry-run。它只读取当前活跃店铺与 SPU 集合，不发网络请求、不写仓库：

```bash
node scripts/sync_full_managed_product_identity_evidence.mjs \
  --config /srv/shein-fm/secrets/supply/openapi.json \
  --now 2026-07-26T20:00:00+08:00 \
  --run-id identity-evidence-20260726-v1
```

数据库连接串只允许通过进程环境中的 `FULL_BI_DATABASE_URL` 注入。禁止使用命令行参数传递连接串，避免凭据出现在进程 `argv`、Shell 历史或运维采集记录中。

确认输出的店铺数、SPU 数和 `planHash` 后，用完全相同的 `--now / --run-id / --languages / --stores / --limit` 加：

```text
--apply --approved-hash <64位planHash>
```

每个 SPU 网络请求在数据库事务外完成；每个 SKU 在一个短事务中建立 `BUILDING` 观察集、写入分层成员、核对数量和指纹，再一次封存为 `SEALED`。同一幂等键内容漂移会整笔回滚。

### 2. 生成候选

候选规划器只读取 `SEALED` 观察集，不持有 OpenAPI 凭据。候选必须引用：

- 来源观察集和目标观察集；
- 两边具体 identifier observation；
- 匹配或硬冲突类型；
- matcher 版本、证据集合指纹和计划 hash。

调用方不能传入临时 `sourceProfile / targetProfile` 生成候选。通用核心属性只能加辅助分，只有明确白名单的官方属性才能参与自动门禁。

### 3. 决定与映射

- `list / show` 对所有员工开放只读查看。
- `decide` 默认 dry-run；执行时必须给确认字面量和当前计划 hash。
- 一次只处理一个店铺 SKU。
- 事务统一锁定 `dim.full_sku`，再回读候选、证据、当前映射和最后决定，防止两个候选并发改写同一 SKU。
- assignment 必须通过复合外键证明它与同一个 candidate、decision、SKU、标准商品和变体一致。
- 跨店标准商品使用 `GLOBAL` 身份；未满足跨店证据的店内商品只能是 `LOCAL_SINGLETON`，门户必须显示“店内标准商品（待跨店归并）”，不能伪装为跨店已确认。

## 自动确认规则

零硬冲突、分数不低于 `0.95` 且至少两类独立强证据之外，还必须命中下列路径之一：

1. 有效 GTIN + 官方型号；
2. 有效 GTIN + 品牌/末级分类 + 至少两个白名单规格；
3. 官方型号 + 品牌/末级分类 + 相同供应商货号 + 至少两个白名单规格。

首批白名单属性 ID：

```text
147, 160, 1000463, 1000572, 1000616, 1000838,
1001207, 1001466, 1001607, 1001755, 1002322, 1002323
```

白名单必须按官方属性语义和分类持续审计。相同标题、相同图片 URL、相同供应商货号、相同商家 SKU 或任意两个未审计属性都不能单独自动确认。

## 门户口径

- 首页“标准商品排行”只汇总 `GLOBAL + CONFIRMED` 映射，并同时显示覆盖 SKU、待归并 SKU 和数据质量。
- `LOCAL_SINGLETON` 可以形成安全的店内商品主档，但只进入“店内标准商品（待跨店归并）”排行。
- 未映射 SKU 始终保留店铺、平台 SKU/SKC/SPU 和原始货号，不能跨店按裸值求和。
- 标准商品映射不足时，应显示原因和下一步，不能用空排行冒充零销量。
